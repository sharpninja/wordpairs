# Acceptance Criteria to Test Inventory

**Requirements baseline:** `word_association_game_requirements.md` v2.6  
**Status:** Planned traceability inventory; no test code is authored, mock-validated, or passing yet

This inventory decomposes the 45 active acceptance criteria into proposed test cases with criterion-specific assertions and seams. Six retired IDs remain reserved: AC-34, AC-35, AC-36, AC-40, AC-48, and AC-49 are technical-requirement checks, not acceptance criteria. It establishes planned traceability only: it is not evidence of implemented test coverage. Phase 0 was approved on 26 October 2026. Requirements v2.6 fixes expected results for all active ACs; the planned cases now guide exact assertions, mock behavior and evidence tiers. Test authoring and mock validation are authorized and underway; all 45 active-AC tests must pass against mocks before any project implementation code. Real database/provider checks are separate evidence tiers. All deployment checks map to TRs only, are not AC-bound, and cannot replace mock AC coverage. Execute real-system checks at their appropriate post-adapter/release stages. The mock-validated application contracts remain in the regression suite.

## Implementation evidence

For every mock-gate contract test ID, record its test file/name, mock-validation command and result before the first implementation commit, then record production commit and full-suite regression result. For every post-implementation integration evidence ID, record its actual database/provider/browser command and result when the required system exists; deployment/account checks are recorded against TRs only. These IDs are not represented as mock proof. A fake may validate the application contract at its port but must not be cited as proof that the underlying database serializes concurrent writes or commits an outbox atomically.

# Acceptance Criteria to Test Inventory

**Requirements baseline:** `word_association_game_requirements.md` v2.3  
**Status:** Planned traceability inventory; no test code is authored, mock-validated, or passing yet

This inventory decomposes the active acceptance criteria into proposed test cases with criterion-specific assertions and seams. It establishes planned traceability only: it is not evidence of implemented test coverage. Phase 0 is planning-only, so executable tests are not authored until Phase 0 passes. Before Phase 0 approval, every active AC must have a fixed expected result: resolve decisions that affect assertions or formally revise the AC out of the active baseline. After Phase 0 approval, author and mock-validate the complete active-AC contract suite before any project implementation code. Real database, provider, deployment, and human checks are separate evidence tiers, not mocked claims; define them now and execute them at their appropriate post-adapter/release stages. The mock-validated application contracts remain in the regression suite.
